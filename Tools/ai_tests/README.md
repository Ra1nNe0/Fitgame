# Автотест распознавания движений

Проверка классификатора `PoseMotionClassifier` без камеры и без Unity.

1. `gen_sequences.py` строит 3D-модель человека (длины костей, суставы), выполняет прыжки, приседания,
   удары, подъём рук, их недоделанные варианты и «бытовые» движения (покачивание, ходьба на месте,
   почесать голову, хлопки, наклон, стойка), проецирует в камеру и пишет пакеты в формате сервера (`FQ1|pose|...`).
   Каждая попытка подписана ожидаемым ответом.
2. `Harness.cs` подаёт пакеты в классификатор и считает матрицу ошибок, точность и задержку.

```
python gen_sequences.py 1 2.6 > seq.txt        # зерно 1, камера в 2.6 м
mcs -out:harness.exe Harness.cs ../../FitQuest/FitQuest/Assets/Scripts/Motion/{MotionType,PosePacket,PoseMotionClassifier}.cs
mono harness.exe seq.txt                       # или dotnet/csc; второй аргумент — строгость
```

Результаты последнего прогона — в `results.txt`.

## Позы ритм-режима

`gen_rhythm.py` (та же модель тела) делает позы-стрелки: рука влево, рука вправо, обе руки в стороны,
руки вверх (вперёд и через стороны — по дороге руки проходят «в сторону», но стрелки нажиматься не должны),
присед, а также движения, которые ничего нажимать не должны (рука чуть отведена, удар вперёд, лёгкое
пружинение, покачивание, ходьба, почесать голову, хлопки, стойка). `RhythmHarness.cs` проверяет `RhythmPoseTracker`.

```
python gen_rhythm.py 1 2.6 > r1.txt
csc -out:rh.exe RhythmHarness.cs ../../FitQuest/FitQuest/Assets/Scripts/Motion/{PosePacket,RhythmPoseTracker}.cs
rh.exe r1.txt          # второй аргумент — строгость
```

Результаты — в `rhythm_results.txt`. «Задержка от начала» считается от начала движения, поэтому включает время,
пока игрок поднимает руку; задержку камеры в самой игре подбирает экран итогов ритм-баттла. Это проверка логики на идеализированных данных;
точность на живой камере измеряется в игре: «Камера и AI» → «Тест AI» (отчёт CSV в папке данных игры).
